## 1. Final architecture doctrine

Founder-led Sales is a nonlinear decision runtime for a specific buying situation.

The governing loop is:

```text
OBSERVE REALITY
      ↓
UPDATE EVIDENCE / BUYER CONDITIONS
      ↓
IDENTIFY UNRESOLVED DECISION WORK
      ↓
ROUTE TO DOMAIN OWNER
      ↓
PROPOSE MINIMUM VALID INTERVENTION
      ↓
FS1 RESOURCE GATE
      ↓
EXECUTE ONLY IF JUSTIFIED
      ↓
OBSERVE RESULT
      ↓
FS8 RECORDS STATE CHANGE
      ↓
REASSESS / ROUTE AGAIN
```

Routing follows the current decision job, not seller stage, artifact name, topic noun, ACV, company size, or methodology checklist.

## 2. Boundary repair — one owner for pursuit allocation

Several tracks can discover that their local work should stop, wait, or reroute. They must not independently set global pursuit truth.

Freeze:

```text
LOCAL CAPABILITY OUTCOME
≠
GLOBAL PURSUIT DECISION
```

Semantics:

```text
FS3 local stop
= no worthwhile access transition remains now

FS5 STOP_PROVING
= no worthwhile evidence intervention remains

FS6 local stop
= no current viable buyer-decision intervention identified

FS7 WALK
= current commercial package/path is unacceptable

FS1 STOPPED
= no attractive next pursuit investment remains
```

**FS1 is the sole owner of global pursuit allocation.**

FS8 records pursuit state and history but does not independently decide pursuit economics.

## 3. Boundary repair — normalize evidence representation

The tracks used different evidence vocabularies during research. Preserve their distinctions without maintaining incompatible status enums.

Use a shared evidence envelope:

```text
CLAIM
What proposition is being considered?

EPISTEMIC FORM
reported / observed / verified / inferred / hypothesis

SUPPORT STATUS
supported / contradicted / ambiguous / missing

PROVENANCE
Who or what produced the evidence?

SCOPE
actor / team / function / account / buying situation / population

FRESHNESS
current / stale / superseded

EVIDENCE
What specifically supports the status?

OBSERVED_AT
When was it established?
```

Rules:

```text
buyer statement ≠ verified fact
signal ≠ buyer fact
inference ≠ observation
old evidence ≠ current evidence
more observations ≠ independent evidence
```

`FORBIDDEN INFERENCE` is a reasoning constraint, not an evidence status.

`COMMITTED` belongs to commitment state, not evidence state.

## 4. Boundary repair — one commitment object

`Commitment` appeared in multiple tracks with different meanings. Use one lifecycle object and let each track own only the semantics of the commitment it creates or reads.

Canonical commitment:

```text
ACTOR
ACTION / OBLIGATION
PURPOSE
AFFECTED_CONDITION
DUE / TRIGGER
STATUS
FULFILLMENT_EVIDENCE
```

Lifecycle:

```text
PROPOSED
→ ACCEPTED
→ OWNED
→ DUE
→ FULFILLED / MISSED / RENEGOTIATED / WITHDRAWN
```

Ownership:

```text
FS3
sizes the access / interaction ask

FS5
defines buyer contribution required for valid evaluation

FS6
determines whether a justified substantive commitment can be formed

FS7
defines commercial obligations

FS8
tracks commitment lifecycle and history
```

To avoid semantic collision, FS3 should prefer **Minimum Sufficient Ask** over `Minimum Sufficient Commitment`.

## 5. Boundary repair — FS3 does not choose proof

FS3 owns access mechanics.

FS5 owns evidence-mechanism selection.

Freeze:

```text
FS5
WHAT evidence mechanism is required?

targeted demo?
reference?
technical test?
POC?
pilot?
docs?

FS1
Is producing that evidence worth scarce resources?

FS3
HOW is the required access/interface obtained?

async?

through whom?
direct?

```

A request to `run a POC` does not automatically make the problem an FS5 problem. Route by the decision job the requested artifact is supposed to perform.

## 6. Boundary repair — FS2 proposes candidates; FS1 activates capacity

FS2 owns whether a concrete `Account × Buying Situation` is sufficiently evidence-backed to merit consideration or further discrimination.

FS1 owns whether scarce capacity should be allocated now.

Therefore:

```text
FS2
credible candidate

≠

FS1
active pursuit
```

A strong opportunity can legitimately be `QUEUED` because other uses of constrained capacity dominate it.

## 7. Boundary repair — FS4 diagnosis does not become global qualification

FS4 owns buyer-reality reconstruction:

```text
current reality
problem / symptom
causal hypotheses
rival explanations
consequence
desired change
status quo
change motive
constraints
```

FS4 may establish:

```text
No consequential problem is currently supported.
```

But FS4 does not set final global pursuit state.

Its output should remain:

```text
diagnosis state
change-case state
decision-critical uncertainty
diagnosis-derived viability signals
```

FS1 determines the resource-allocation consequence.

## 8. Boundary repair — FS7 economics vs FS1 economics

FS7 owns whether the **current commercial package** is acceptable.

FS1 owns whether spending the **next scarce unit of pursuit resource** to obtain an agreement remains worthwhile relative to alternatives.

Example:

```text
Buyer requests six weeks of custom engineering.

FS7
→ package delta
→ seller exposure
→ candidate counter / resize

FS1
→ compare six-week burden against alternatives
→ continue or globally stop
```

The same evidence can inform both decisions without duplicating ownership.

## 11. Reopen conditions

Reopen architecture only on a demonstrated failure class:

```text
UNROUTABLE
No FS can own the required decision.

DUAL_OWNER
Two FS must independently own the same decision.

STATE_LOSS
Required information cannot survive handoff.

WRONG_PATH
A plausible answer is produced through the wrong capability owner.

LOCAL_GLOBAL_COLLAPSE
A local outcome becomes global pursuit truth.

EVIDENCE_LAUNDERING
A claim becomes stronger across handoff without stronger evidence.

COMMITMENT_LAUNDERING
Interest, ask, action and commercial obligation are silently collapsed.

IRREVERSIBLE_OVERCOMMIT
Scarce or irreversible resources are committed before the FS1 gate.
```

No new sales framework, score, stage, acronym, or primitive should be added without one of these concrete failures.
