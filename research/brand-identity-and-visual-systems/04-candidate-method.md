# Brand Identity and Visual Systems — Candidate Method

Status: **WORKING THEORY CANDIDATE — NOT RUNTIME GUIDANCE**

This document translates the first research pass into a candidate practitioner method. It is intentionally more operational than `00-research-brief.md`, but it is not yet a frozen theory and must not be treated as runtime instruction until adversarial review.

The central design principle is:

```text
DO NOT FORCE EVERY IDENTITY TASK THROUGH A FULL BRANDING PROCESS.
START FROM THE CURRENT OPEN IDENTITY DECISION.
```

The candidate method is therefore a set of decision gates, not a mandatory sequence.

---

## 1. Governing state model

A visual-identity task begins with four state buckets:

```text
RESOLVED STRATEGIC STATE
What is already sufficiently established and should not be reopened?

OPEN IDENTITY DECISION
What visual choice actually remains unresolved?

EVIDENCE / CONSTRAINTS
What facts, observations, existing assets, deployment needs,
and authoritative constraints can change the decision?

UNKNOWN / ASSUMED
What is not established and should not be converted into design fact?
```

Typical resolved inputs may include:

- brand/product name;
- audience/context;
- category or frame;
- relevant alternatives;
- primary value / positioning;
- existing brand equity;
- required personality or expression constraints;
- markets/languages;
- deployment surfaces;
- existing legal or organizational constraints.

The candidate method must not automatically rebuild these inputs.

---

# Gate A — Identity scope

Ask internally:

> What identity decision is actually open?

Possible jobs include:

```text
CREATE
new identity or new visual asset

REVISE
change an existing identity while preserving relevant equity

REFINE
improve geometry/typography/form without reopening concept

EXTEND
carry a resolved identity into another asset or surface

EVALUATE
review candidate identity work

RECOVER
reconstruct a usable system from inconsistent existing assets
```

This is not a new top-level controller taxonomy. It is a local decomposition inside a possible identity capability.

### Fast-path examples

```text
“Make this supplied symbol less top-heavy.”
→ REFINE
→ do not reopen positioning

“Create a favicon variant of this approved mark.”
→ EXTEND
→ load only small-size / geometry constraints

“Should we throw away our current symbol in the rebrand?”
→ REVISE
→ existing-equity evidence becomes material
```

---

# Gate B — Minimum strategic identity brief

Load this gate only when visual exploration would otherwise be unguided.

A minimum brief should answer only the dimensions that can change the visual decision:

```text
IDENTITY SUBJECT
What entity must be identified?

TARGET CONTEXT
Where / for whom must identification work?

CATEGORY / FRAME
What space must the identity operate inside or against?

DESIRED ASSOCIATIONS / CHARACTER
What should the system plausibly support or avoid signaling?

EXISTING EQUITY
What learned or operational assets may need preservation?

NEGATIVE SIGNALS
What readings would materially contradict the brand/job?

DEPLOYMENT ENVIRONMENTS
Where must the identity survive?
```

If positioning/value is materially unresolved, hand off upstream. If it is resolved, freeze it.

Do not demand a 50-question brand workshop when seven supplied facts are enough.

---

# Gate C — Existing-asset / category context

This gate exists to prevent two opposite failures:

```text
CATEGORY MIMICRY
“We are AI, so use sparkle + gradient + nodes.”

CATEGORY IGNORANCE
“Be unique” while accidentally reproducing a competitor cue.
```

The audit should be decision-relative, not a giant inspiration scrape.

Possible observations:

```text
recurring symbol families
recurring silhouettes
recurring geometric grammar
recurring color territory
recurring type treatment
category-coded metaphors
competitor-owned or strongly associated assets
pre-existing mental competition
current brand assets and lineage
obvious visual confusion zones
```

### Output

A small **competition / convention map**, not a moodboard dump.

For each relevant cue:

```text
CUE
WHY IT IS COMMON / MEANINGFUL
POTENTIAL BENEFIT
MENTAL-COMPETITION / CONFUSION RISK
DECISION IMPLICATION
```

Do not infer actual distinctive-asset Fame or Uniqueness without buyer evidence.

---

# Gate D — Concept territories

Before drawing one final mark, create multiple genuinely different **visual hypotheses** when exploration is open.

A territory is not an icon.

Candidate representation:

```text
TERRITORY NAME
strategic idea
visual grammar
what it deliberately does not encode
why it fits the current identity job
likely category/genericity risk
likely perceptual/misread risk
system-extension potential
```

Good territory separation changes the underlying visual logic, not just surface decoration.

Example:

```text
BAD DIVERSITY
sparkle A
sparkle B
sparkle C

BETTER DIVERSITY
gesture / interaction
workspace / surface
signal / transition
custom typographic ownership
```

The objective is not to maximize the number of concepts. It is to avoid premature convergence on the model’s first cliché.

---

# Gate E — Form-family exploration

After a promising territory exists, explore **form families** before refining one exact drawing.

Possible families include:

```text
continuous stroke
open geometry
solid geometric mark
negative-space construction
custom glyph
monogram
asymmetric capsule
organic loop
modular / repeated unit
wordmark-led identity
```

These are examples, not a taxonomy.

The important rule is:

```text
TERRITORY
→ MULTIPLE FORM GRAMMARS
→ SELECT PROMISING FAMILY
→ ONLY THEN MICRO-REFINE
```

This reduces the common failure where every generation changes concept, silhouette, stroke, color, perspective, and symbolism simultaneously.

---

# Gate F — Candidate screening

Do not collapse screening into a pseudo-objective total score.

Evaluate the dimensions separately and preserve trade-offs.

Candidate dimensions:

```text
STRATEGIC CONGRUENCE
Does the candidate plausibly support the resolved identity job?

PERCEPTUAL READING
What does the mark look like before the explanation is supplied?

UNINTENDED MEANING
What materially harmful or distracting alternative readings appear?

FORMAL COHERENCE
Does the construction feel internally deliberate rather than accidentally inconsistent?

DISTINCTIVENESS POTENTIAL
Does it avoid obvious competitor/category mental competition?

EXISTING-EQUITY FIT
Does it preserve or intentionally retire known prior cues?

DEPLOYMENT FITNESS
Can it survive the required surfaces?

SYSTEM POTENTIAL
Can the visual logic extend when extension is actually required?

RIGHTS / LEGAL RISK
Is there an obvious dependency or conflict requiring further search/review?
```

### Misread test

A useful perceptual question is:

> Without the rationale or brand name, what else could this mark reasonably be read as?

This is not a demand that every logo have one literal interpretation. It is a way to detect unintended readings that materially change the decision.

Do not reject harmless ambiguity merely because viewers describe different abstract forms.

---

# Gate G — Controlled refinement

Once a family is chosen, freeze its identity enough that each iteration is interpretable.

Instead of:

```text
“Make it better.”
```

use deliberate mutations such as:

```text
A — baseline
B — wider aperture
C — tighter aperture
D — softer terminal
E — heavier mass / stroke
F — reduced asymmetry
```

Potential controllable variables include:

```text
silhouette
aperture
stroke / mass
corner language
terminal
counterspace
symmetry / asymmetry
orientation
spacing
optical center
wordmark-mark relationship
```

The method should preserve one-variable or one-related-variable-family comparisons when possible.

This does not mean formal A/B testing is required for every micro-adjustment. The purpose is causal interpretability inside the design process:

```text
WHAT CHANGED?
WHAT IMPROVED / DEGRADED?
WHAT REMAINS OPEN?
```

# Gate H — Perceptual and deployment stress tests

Tests should follow the stated deployment environments rather than a universal asset checklist.

Common digital identity conditions may include:

```text
monochrome
positive / reversed
light / dark background
16 px
24 px
32 px
64 px
favicon
social avatar
web header
app/product navigation
large display
busy / image background when actually required
```

Other environments may require:

```text
print
embroidery
engraving
packaging
signage
motion
low-quality reproduction
```

### What to inspect

```text
silhouette survival
counter closure
stroke disappearance
visual weight
optical centering
internal gaps
wordmark legibility
positive/reversed behavior
container fit
unintended shape emergence
```

Do not copy another company’s exact clear-space or minimum-size ratios as universal law.

If the mark needs a small-size optical variant, document it explicitly rather than pretending one master drawing must work unchanged everywhere.

# Gate I — Distinctiveness and existing-equity decision

The candidate method uses three separate questions.

## I1. Distinctiveness potential

For a new/unfamiliar asset:

```text
Is the design unlike obvious competitor/category cues?
Could a rival plausibly use the same cue tomorrow with little confusion?
Is there strong pre-existing mental competition?
```

This is **potential**, not measured asset strength.

## I2. Learned distinctive-asset strength

For an established asset, use consumer/category-buyer evidence when consequential.

Relevant measures may include Fame and Uniqueness or other valid recognition/attribution research.

Do not replace buyer evidence with:

```text
“our team recognizes it instantly”
“we have used it for ten years”
“the designer says it is iconic”
```

Historical use can justify preserving uncertainty and testing before removal, but does not prove buyer memory.

## I3. Equity action

Possible bounded actions:

```text
PRESERVE
strong/valuable cue should remain substantially stable

EVOLVE
retain recognizable lineage while correcting a real problem

BUILD
new cue has promising uniqueness but low/no learned Fame

DE-EMPHASIZE
cue creates category confusion or is operationally weak

RETIRE
evidence supports removal and replacement risk is acceptable
```

These labels are candidate practitioner language, not durable runtime primitives.

---

# Gate J — Legal / rights pre-flight

Activate only when consequential use or the user’s request makes it material.

Possible pre-flight actions:

```text
verbal mark search
figurative/image-similarity search
relevant goods/services classification awareness
jurisdiction scope check
obvious third-party asset/license dependency check
```

### Allowed conclusion form

```text
SEARCHED SCOPE
OBSERVED CANDIDATES / CONFLICTS
WHY THEY MAY MATTER
WHAT REMAINS UNSEARCHED / UNRESOLVED
WHEN PROFESSIONAL CLEARANCE IS NEEDED
```

Never convert a bounded search into legal certainty.

---

# Gate K — System commit and stewardship

Commit only the system required by the job.

Possible retained state:

```text
primary mark
wordmark / lockup relationships
approved variants
small-size optical variant if needed
monochrome / reversed behavior
core geometry relationships
color roles
primary typography relationships
motion behavior when part of identity
patterns / graphic devices when part of identity
asset hierarchy
clear-space principle
minimum-use constraints
misuse boundaries
known semantic risks
known legal uncertainty
source / creation provenance when material
```

The objective is not a giant brand-guidelines document.

The objective is to preserve enough decision state that later agents/users do not unintentionally drift the identity.

## 2. Candidate operating patterns

### New identity

```text
freeze resolved upstream state
→ minimum brief
→ category / existing-context audit
→ concept territories
→ form families
→ candidate screening
→ controlled refinement
→ deployment tests
→ distinctiveness / legal pre-flight as needed
→ system commit
```

### Existing logo geometry refinement

```text
freeze concept
→ identify formal defect / open variable
→ controlled refinement
→ deployment stress test
→ commit corrected master
```

### Rebrand / redesign

```text
current identity audit
→ evidence of existing asset strength when material
→ define what problem actually requires change
→ preserve / evolve / replace decision
→ explore only the dimensions reopened by that decision
→ test lineage + deployment + confusion
→ commit
```

### Existing identity review

```text
state the identity job
→ inspect strategic congruence
→ perceptual readings / misreads
→ deployment failures
→ mental competition / evidence strength
→ legal dependency if consequential
→ recommend preserve / refine / test / replace
```

## 3. Anti-patterns

```text
PROMPT → PRETTY IMAGE → APPROVE

CATEGORY NOUN → LITERAL ICON

BRAND ADJECTIVE → FIXED SHAPE RULE

AI / TECH → BLUE-PURPLE GRADIENT + SPARKLE + NODE GRAPH

“MEMORABLE” WITHOUT RECOGNITION / ATTRIBUTION EVIDENCE

“DISTINCTIVE” BECAUSE DESIGNER SAYS SO

REDESIGN BECAUSE CURRENT MARK FEELS OLD

NEW VERSION CHANGES FIVE VARIABLES AT ONCE

ONE 0–100 LOGO SCORE

MOCKUP QUALITY USED AS LOGO QUALITY

IMAGE SEARCH RETURNS NOTHING → TRADEMARK SAFE

RASTER GENERATION → FINAL MASTER WITHOUT GEOMETRY CHECK
```

## 4. Candidate evaluation contract

A good identity recommendation should be able to answer:

```text
WHAT DECISION WAS OPEN?
WHAT STATE WAS FROZEN?
WHICH EVIDENCE / CONSTRAINTS CHANGED THE DECISION?
WHICH ALTERNATIVES WERE GENUINELY DIFFERENT?
WHAT WAS OBSERVED, NOT JUST EXPLAINED?
WHAT TRADE-OFF REMAINS?
WHAT DEPLOYMENT CONDITIONS WERE ACTUALLY TESTED?
WHAT CAN / CANNOT BE CLAIMED ABOUT DISTINCTIVENESS?
WHAT LEGAL / RIGHTS UNCERTAINTY REMAINS?
WHAT EXACT STATE IS NOW COMMITTED?
```

If the method cannot answer those questions, it is probably still operating as aesthetic preference rather than a governed marketing decision.

## 5. Open theoretical questions before freeze

1. Should the capability remain **visual identity**, or broaden to distinctive brand assets that include sonic/verbal assets? Current evidence supports system thinking, but broadening may overlap Chapter 04 and future audio-specific reasoning.
2. Does concept-territory formation require a dedicated route, or can it remain local prose inside a smaller number of routes?
3. Should perceptual testing and distinctiveness measurement be one route or separate because they answer different estimands?
4. How much production guidance belongs in runtime knowledge versus external specialist handoff?
5. What exact boundary should trigger Chapter 07 for cross-cultural visual meaning?
6. What minimum evidence is required before recommending retirement of an established asset?
7. Can a dedicated identity owner be justified without adding a new controller job? Current hypothesis: yes, as a JIT knowledge namespace under existing `CREATE / REVISE / EVALUATE`-type jobs, but this must be pressure-tested.
