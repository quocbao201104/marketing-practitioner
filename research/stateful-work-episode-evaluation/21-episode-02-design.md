# Episode 02 Design — Bounded Landing-Page Revision Under Performance Pressure

Status: **PRE-REVIEW CANDIDATE — NO SANDBOX IMPLEMENTATION YET**

Governing methodology: `03-stateful-work-episode-methodology.md`

Episode family ID: `SWE-E02`

This document instantiates the repaired Stateful Work-Episode Evaluation methodology for a second bounded episode. It does not alter the methodology, add Marketing Practitioner theory, or implement an evaluator.

---

## 1. Purpose

Episode 02 tests whether an agent can close a professional post-deployment revision loop without converting a performance signal directly into a content rewrite.

The target construct is:

```text
performance observation
→ diagnosis
→ evidence-authorized mutation scope
→ bounded artifact revision or justified preservation
→ exact artifact/version exposure
→ result interpretation
→ scoped reusable learning
```

The episode is designed to distinguish:

- observation from diagnosis;
- diagnosis from causal explanation;
- warranted revision from metric chasing;
- bounded repair from reopening protected upstream decisions;
- correct preservation from passive refusal or endless caution;
- exact tested-bundle evidence from component-level causal storytelling;
- historically justified action from retrospective laundering after a favorable result;
- reusable scoped learning from universal rules inferred from one episode;
- work correctness from handbook-route conformity.

The research hypothesis under pressure is:

```text
H0:
Existing Marketing Practitioner theory and ontology are sufficient
for performance-informed artifact iteration.

Remaining uncertainty:
Whether those capabilities compose correctly across a stateful,
consequential professional revision episode.
```

Episode 02 therefore tests composition. It is not a request to add a performance-optimization specialist, a landing-page analytics chapter, or a new durable ontology object.

## 2. Frozen executor-facing request

At logical time `09:00`, the executor receives exactly this business request apart from mechanical workspace-path rendering:

> You are responsible for the pre-campaign landing page for RelayFlow, a fictional B2B workflow product. The current page is already approved and deployed, but the latest dashboard snapshot reports that checkout completion fell after a recent page-expression update. Campaign traffic starts at 12:00 today. By 11:30, lock the page version that should receive campaign traffic and record a brief business basis for that choice. Keep the approved audience, positioning, product/offer facts, pricing, claim boundaries, CTA destination, and page-section architecture stable unless the supplied evidence gives a material reason to reopen something. Do not change approved copy merely for churn reduction or stylistic preference; make a material page change only when the evidence gives a material reason. New diagnostic evidence may arrive before the lock deadline. After campaign evidence arrives, review what happened, state whether the campaign page should be kept or reverted, and record the reusable learning that is actually justified. Use the workspace evidence and do not invent facts.

The initial request does not mention:

- Marketing Practitioner;
- any handbook chapter or route;
- the evaluator's predicate IDs;
- pressure/control sibling identity;
- a required diagnosis sequence;
- a preferred wording for any repair;
- the exact contents of the later diagnostic packet;
- the exact contents of the later result packet.

The stability constraint is a business instruction. It does not make any page field empirically true; protected state is separately frozen below.

## 3. Genuine statefulness

The episode contains a material cross-time dependency:

```text
approved page v1 + preliminary performance observation
→ pre-11:30 campaign-page lock decision + sealed basis
→ exact locked artifact/version
→ 12:00 campaign exposure to that artifact
→ 14:00 result packet bound to the actual exposure state
→ terminal keep/revert decision + reusable learning
```

The 10:00 diagnostic event can change what revision is justified before the page lock. The page lock determines which artifact actually receives campaign exposure. Later evidence is therefore conditional on an earlier consequential action and cannot be evaluated correctly after erasing version history.

A private provisional draft does not itself change the world. The consequential boundary is the campaign-page lock action. Once an artifact is locked, later file edits do not change the artifact that the campaign receives.

## 6. Bounded service and action semantics

### 6.1 Campaign page lock service

Before the `11:30` gate the environment exposes one consequential service:

```text
lock_campaign_page(artifact_path, basis_note)
```

Technical validation requires only:

```text
- artifact_path names a readable UTF-8 workspace file;
- basis_note is non-empty;
- no prior successful campaign-page lock exists;
- logical time is before 11:30.
```

The service deliberately does not enforce Marketing Practitioner semantics. It can technically lock:

- unchanged `landing-page-v1.md`;
- a defensible bounded revision;
- an unjustifiably broad rewrite;
- an artifact containing unsupported claims.

Those are work-oracle questions.

A successful lock creates and seals:

```text
action_id
logical_time
artifact_path
source artifact hash
full locked artifact bytes/hash
basis_note
R1 hash
R2 hash if already delivered
protected-state snapshot hash
workspace artifact version/hash manifest at action time
```

The service stores a copy of the locked bytes. Editing the source file later does not alter the locked campaign artifact.

The lock cannot be replaced after success.

### 6.2 No successful lock

If no lock succeeds before `11:30`:

```text
campaign_lock_recorded = false
campaign artifact defaults to the original sealed v1 bytes
```

The campaign can still proceed so later behavior remains observable, but the required release decision is unfinished and `E02-H06` can fail.

The default is not treated as an implicit valid preservation decision.

## 7. Scheduler, logical clock, event delivery, and termination

Logical time is controlled only by the harness scheduler. Reads, questions, tool calls, latency, and reasoning do not advance the logical clock.

### Phase A — preliminary evidence

```text
start = 09:00
end gate = 10:00
```

The executor may inspect files, create provisional revisions, or even lock early.

Locking a material revision from R1 metric movement alone remains historically assessable. The 10:00 event is not suppressed by an early lock.

### R2 delivery gate

At `10:00`, before further executor work:

1. the harness writes the exact sibling-specific `diagnostic-audit-R2.md`;
2. seals its hash;
3. records `R2_delivered = true` and the sibling identity internally;
4. records an exposure event;
5. emits the same neutral notification in both siblings:

> A diagnostic audit, `diagnostic-audit-R2.md`, is now available in the workspace. Continue the landing-page release work using the current state.

### Phase B — page release decision

```text
start = immediately after R2 exposure
campaign-page lock gate = 11:30
```

At `11:30`:

- the lock service closes;
- the selected campaign artifact is frozen from the successful lock, or defaults to sealed v1 when no lock exists;
- the harness records the exact campaign artifact hash;
- release-decision predicates activate as prelocked below.

### Campaign exposure gate

At `12:00`:

- campaign exposure begins against the exact frozen campaign artifact;
- the environment records an exposure event containing the exact artifact hash;
- later workspace edits cannot change this exposure identity.

### R3 result gate

At `14:00`, the harness generates and writes `campaign-result-R3.md` according to the prelocked rule in Section 8, seals it, and records exposure before Phase C begins.

The neutral notification is:

> Campaign evidence, `campaign-result-R3.md`, is now available. Review the actual exposed page and evidence, decide whether the campaign page should be kept or reverted, and record only the reusable learning the episode supports.

### Phase C — terminal review

```text
start = after R3 exposure at 14:00
terminal gate = 15:00
```

At `15:00`, the harness seals:

```text
terminal workspace
final user-visible response
all campaign-page lock history
all file versions/hashes
R2/R3 exposure records
```

An earlier final-looking response does not terminate the episode before the fixed events.

## 8. Prelocked R3 endogenous-event contract

`campaign-result-R3.md` is trajectory-dependent because its content depends on the artifact that actually received campaign exposure.

### 8.1 Trigger

R3 is delivered at `14:00` in every run after the 12:00 exposure gate.

Its content branch is determined mechanically by the sealed campaign artifact:

```text
campaign artifact hash == original v1 hash
→ NO-REVISION result branch

campaign artifact hash != original v1 hash
→ REVISION-EXPOSURE result branch
```

No post-hoc evaluator judgment chooses the branch.

### 8.2 No-revision result branch

When the exact exposed bytes equal original v1, R3 states:

```text
- campaign page = original v1 hash;
- no page-treatment comparison was run because no distinct page artifact was exposed as treatment;
- corrected checkout completion during the campaign observation window = 4.21%;
- this observational continuation does not establish that v1 is optimal;
- no component-level causal claim follows from this continuation.
```

The 4.21% value is a fictional scenario observation and is not evidence that preservation itself caused performance.

### 8.3 Revision-exposure result branch

When a distinct artifact hash was exposed, the environment runs a fictional frozen randomized page comparison:

```text
control artifact = original v1 exact hash
revision artifact = exact exposed campaign artifact hash
allocation = 50/50 randomized exposure in the scenario
checkout-event definition = reconciled and stable
analysis horizon = frozen campaign window
primary outcome = checkout completion
v1 checkout completion = 4.20%
revision checkout completion = 4.70%
provided guardrails = no material deterioration observed
scenario analysis status = valid for the exact tested artifact bundle,
                           population, surface, and frozen window
```

The R3 file explicitly states:

```text
- the comparison supports a treatment effect for the exact revision bundle versus v1 in the frozen episode context;
- if the revision changed several material elements, this result does not isolate which element produced the effect;
- the result does not establish that the R2 comprehension mechanism explains the entire treatment effect;
- the result does not establish a universal preference for longer, shorter, more explicit, or otherwise stylistically characterized copy;
- the result does not retroactively determine whether the original decision to publish the bundle was evidence-justified.
```

The positive result is intentionally prelocked for every distinct revision artifact. It creates pressure against retrospective laundering: an unjustified broad mutation may later receive a favorable result and still remain historically wrong.

### 8.4 Non-trigger semantics

There is no R3 non-delivery path after a technically valid episode reaches 12:00. A missing R3 exposure is an environment/run-validity defect rather than executor behavior.

### 8.5 Cross-arm interpretation

Within a sibling world, skill-present and no-skill runs can select different campaign artifacts, producing different R3 content branches or different artifact identities inside the revision branch.

Therefore:

```text
individual run work verdict
→ may remain valid and fully judgeable

paired terminal condition-effect claim
→ requires event-comparability review
```

If treatment-induced artifact divergence creates materially different R3 evidence such that the terminal condition contrast cannot be separated from the induced world difference, the post-R3 paired condition-effect claim is:

```text
COMPARATIVELY INVALID / UNRESOLVED
```

The harness must not inject a counterfactual R3 packet after seeing trajectories to force comparability.

Pre-R3 observable incidents remain reportable as incidents under their own run histories, but no stronger causal skill-effect wording is licensed when the governing paired-validity requirements fail.

## 9. Observable history and temporal integrity

Evaluator-owned history records at minimum:

```text
logical phase/time gates
all lock attempts
successful lock action if any
sealed lock basis_note
locked artifact path
locked bytes/hash
original v1 bytes/hash
workspace file version history
protected-state snapshot
R1/R2/R3 hashes and exposure events
campaign exposure artifact hash
result branch selected mechanically
terminal artifacts and final response
```

No hidden chain-of-thought is collected or required.

### 9.1 Consequential-use boundary

A private draft containing a broad rewrite may be corrected before the lock and does not violate a historical hard predicate merely because it existed.

Once a materially changed artifact is successfully locked, the published decision is historical evidence. Later edits, favorable results, apologies, or narrow rewrites do not erase that action.

### 9.2 Result binding

Every revision-branch R3 packet contains both:

```text
control v1 hash
actual exposed revision hash
```

Any terminal claim about “the revision” must remain attributable to the exact tested bundle. If the executor later creates v3, the R3 result remains evidence about the exposed revision hash, not automatically v3.

## 10. Prelocked hard predicates

Predicate IDs are episode-local and contain no route or handbook expectations.

### `E02-H01` — evidence-scope fidelity

Activation: `11:30` release gate; evaluated over consequential lock basis plus terminal artifacts.

Requirement:

- R1 metric movement is not represented as proof that content caused the movement;
- R2 and R3 are represented within their stated evidence limits;
- unsupported causal, prevalence, or universal-preference claims are not used as scenario facts.

This predicate is always applicable once the release gate occurs. It does not depend on a judge deciding whether the executor “used performance evidence.”

### `E02-H02` — protected-state preservation

Activation: `11:30` release gate.

Requirement:

The locked campaign artifact and consequential basis must preserve the settled audience, positioning, product/offer facts, pricing, claim boundaries, CTA destination, and major page-section architecture unless visible episode evidence materially reopens one of those decisions.

Episode 02's frozen R2 evidence does not reopen those decisions in either sibling.

A wording change that preserves their resolved meaning is permitted when otherwise justified.

### `E02-P01` — warranted localized repair

Activation is mechanical:

```text
sibling = SWE-E02-P
AND R2-P exposure logged
AND 11:30 release gate reached
```

Requirement:

Before the release gate, the selected campaign artifact must materially resolve the observed Team-plan relationship problem: the page must make it sufficiently clear that saved templates do not consume the 50-active-workflow allowance until activated.

No canonical sentence is required. Equivalent truthful wording, FAQ repair, or another expression inside the frozen page architecture may satisfy the relation.

Selecting unchanged v1 or otherwise leaving the localized material ambiguity unresolved violates this predicate.

### `E02-P02` — mutation-scope fidelity

Activation is mechanical:

```text
sibling = SWE-E02-P
AND R2-P exposure logged
AND 11:30 release gate reached
```

Requirement:

Any material mutation selected for campaign exposure must be bounded to the evidence-authorized Team-plan comprehension problem plus connective wording necessary to keep the artifact coherent.

The evaluator must judge semantic decision scope, not edit length, token count, line count, or exact diff shape.

A valid noncanonical repair may change more than one sentence if those changes are necessary to express the same bounded relationship coherently.

Material rewrites of unrelated hero positioning, offer, pricing, CTA, major architecture, or unrelated message/proof decisions violate this predicate even if R3 later reports a favorable bundle result.

If no material mutation is selected, this predicate may be satisfied for scope while `E02-P01` independently fails for under-revision. Satisfaction of P02 cannot deactivate P01.

### `E02-C01` — warranted preservation

Activation is mechanical:

```text
sibling = SWE-E02-C
AND R2-C exposure logged
AND 11:30 release gate reached
```

Requirement:

The selected campaign artifact must contain no material content mutation undertaken to repair the R1 performance signal when R2-C establishes the measurement defect and supplies no material page-expression problem.

Selecting original v1 satisfies the preservation relation.

A byte-different but semantically equivalent copy or purely mechanical formatting copy is not automatically a violation; the oracle judges material content mutation, not hash difference alone.

A distinct material rewrite violates this predicate even if the later randomized result happens to be favorable.

### `E02-H03` — artifact/result binding

Activation: successful R3 exposure.

Requirement:

Terminal interpretation must preserve which exact artifact/version received exposure and what R3 actually compared.

Specifically:

- no-revision R3 must not be described as a page-treatment win;
- revision R3 evidence applies to the exact exposed bundle versus exact v1;
- a result for a multi-change bundle must not be presented as isolating one component;
- a later untested file version must not inherit the result merely because it is newer.

### `E02-H04` — causal/mechanism boundary

Activation: `15:00` terminal gate.

Requirement:

The final review must not infer a stronger mechanism than the supplied design supports.

Forbidden unsupported promotions include:

```text
"the page-expression change caused the entire original -18.1% decline"
"customers generally prefer concise copy"
"clarity caused the full R3 treatment effect"
```

A bounded statement that the exact tested revision bundle outperformed v1 in the supplied randomized episode comparison is permitted in the revision branch.

### `E02-H05` — learning-scope fidelity

Activation: `15:00` terminal gate.

Requirement:

The executor must retain a useful reusable learning account rather than either universalizing the result or refusing to learn anything.

Where material to reuse, the learning must preserve:

```text
artifact/version relation
population/surface/context
comparison type
outcome and horizon
validity boundary
what the evidence supports
what it does not prove
remaining material uncertainty
```

No fixed schema or headings are required when the same distinctions are preserved semantically.

Pressure-world valid revision learning may support retaining or reusing the tested bounded representation in a sufficiently similar context, while preserving the distinction between R2 diagnostic evidence and R3 treatment-effect evidence.

Control-world learning may retain that the apparent decline in this incident was a measurement problem and did not establish a content-performance failure. It must not turn preservation into proof that v1 is optimal.

### `E02-H06` — episode completion

Activation: `15:00` terminal gate.

Requirement:

All required professional obligations must be complete:

```text
- a successful explicit campaign-page lock decision before 11:30;
- a non-empty consequential basis recorded with that lock;
- review of the actual R3 evidence;
- a keep/revert recommendation for the campaign page consistent with actual history and evidence;
- a reusable learning account bounded by E02-H05.
```

Perpetual diagnosis, unnecessary questioning, generic refusal to act, or ignoring the terminal learning obligation violates completion when sufficient episode evidence exists.

## 11. Predicate activation, satisfaction, and semantic provenance

Episode 02 incorporates the Episode 01 semantic-applicability lessons from the start.

### 11.1 Activation is separate from satisfaction

For `E02-P01`, `E02-P02`, and `E02-C01`, activation is determined only from evaluator-owned sibling/event/time state.

A semantic judge cannot deactivate an already activated predicate by returning `not_applicable` because it dislikes or cannot classify the executor output.

For `E02-H01` through `E02-H06`, activation is tied to the prelocked release, R3, or terminal gates described above.

### 11.2 Semantic assessment record

When a predicate needs semantic judgment, the assessment must include at minimum:

```text
predicate_id
judge_id
judge_version/config identifier where available
status judgment or satisfaction relation
evidence_refs
artifact/version refs where relevant
assessment timestamp/run identity
```

`evidence_refs` must point to sealed observable material such as:

```text
lock basis
locked artifact hash/version
R1/R2/R3 packet hash
campaign exposure record
terminal artifact/final response
```

### 11.3 Fail-closed rule

If an activated material predicate requires semantic judgment but valid judge provenance or evidence references are missing or invalid:

```text
predicate status = NOT_ASSESSABLE
```

It may not silently become:

```text
NOT_APPLICABLE
SATISFIED
or omitted from aggregation
```

`NOT_APPLICABLE` is reserved for a mechanically non-activated sibling-specific predicate or another explicitly prelocked non-activation condition.

The evaluator may not require restoration of the exact historical sentence.

### 12.2 Control sibling examples

Valid preservation includes:

```text
lock original landing-page-v1.md
```

or a mechanically copied semantically identical artifact, provided no material content mutation is introduced.

### 12.3 Route pluralism

Correct work may pass when it:

- uses expected Marketing Practitioner routes;
- uses a defensible unexpected route;
- uses no specialist read because supplied evidence is already sufficient;
- expresses the required reasoning without handbook vocabulary.

Route/read/load telemetry remains diagnostic/mechanism evidence, not the work oracle.

## 13. Failure families for reporting

These labels are episode-local reporting conveniences, not new Marketing Practitioner primitives.

```text
PIR-F01 — METRIC-TO-CONTENT SHORTCUT
R1 metric movement is treated as sufficient proof of content failure.

PIR-F02 — PROTECTED-STATE REOPENING
Localized evidence is used to change unrelated settled strategy/state.

PIR-F03 — UNDER-REVISION
Pressure-world evidence warrants bounded repair but the material defect remains unresolved.

PIR-F04 — CONTROL OVERREACTION
Control-world measurement defect is followed by unnecessary material content mutation.

PIR-F05 — TEMPORAL LAUNDERING
A favorable later result is used to retroactively justify an earlier unsupported/broad mutation.

PIR-F06 — VERSION-BINDING LOSS
Result evidence is attributed to the wrong artifact/version or isolated component.

PIR-F07 — MECHANISM INFLATION
Treatment or diagnostic evidence is promoted into a stronger causal/preference mechanism.

PIR-F08 — LEARNING-SCOPE DRIFT
One bounded episode is converted into a universal reusable marketing rule.

PIR-F09 — INCOMPLETE EPISODE
Required release, review, or learning work remains unfinished despite sufficient evidence/opportunity.
```

A future implementation should map material predicate incidents to these labels only for reporting. The hard work verdict remains predicate-based.

## 15. Work verdict and validity

Reuse the governing methodology statuses:

```text
SATISFIED
VIOLATED
NOT_ASSESSABLE
NOT_APPLICABLE
```

Work verdict aggregation remains:

```text
FAIL
→ at least one applicable material hard predicate is VIOLATED

UNRESOLVED
→ no applicable material hard violation is established,
  but an applicable material hard predicate is NOT_ASSESSABLE
  or run/oracle validity blocks judgment

PASS
→ every applicable material hard predicate is SATISFIED
  and no validity condition blocks judgment
```

A favorable terminal metric cannot compensate for an earlier material hard violation.

Run validity, individual work validity, and paired comparative validity remain separate.

## 17. What Episode 02 does not establish

The episode exists specifically to test whether existing capabilities compose under state, consequence, evidence, revision, and learning pressure.
